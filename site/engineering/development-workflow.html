研发工程与演进

开发与验证工作流

统一入口 facrictl、C++20 4+1 构建、ROS 2 联调与运行基线核验

研发工作区以 main 分支作为统一代码基线，新任务应基于主干拉取独立开发分支推进。所有代码修改均须依据 docs/development/ponytail-full.md 执行完整调用者追踪，保留标定校验、输入门禁与真实失败证据，并在提交前按修改面跑完最小充分验证集。日常操作命令汇总见 快速开始 与 CLI 与场景目录。

一、统一控制台与场景入口：facrictl

仓库根目录入口脚本 facrictl（由 deployment/system_entry.py 实现）自动隔离宿主机 Docker 上下文环境变量并发起受控会话：

常用命令 实际行为与边界
facrictl start [--mock\|--real] [--wait] 默认 --mock 启动模拟真机同步仿真；加 --real 后经 FastDDS Domain 126 连接外部真实机器设备
facrictl start --setup c919 / --scene c919 拉起 C919 机坪多异构本体调度与场景演示入口（对应 --setup factory\|cell\|c919 分派）
facrictl plan [--mock\|--real] / facrictl check [--mock\|--real] 输出启动依赖与参数规划，或执行零积分物理代价的静态预检，不实际启动仿真容器
facrictl status / facrictl review 查看当前工厂运行锁与容器活跃度，或审阅上一轮关闭后的结算摘要
facrictl stop / facrictl close [--wait] stop 执行安全停车同时维持容器与 :18640 控制台在线；close 执行完整关闭、清理容器并等待锁释放（遵循唯一人工停机主权）
facrictl ui 启动或复用系统内已运行的协作控制台界面（deployment/collaboration_launcher.py）

二、分模块构建与多层次回归命令

根据实际改动位置选择对应编译与检查命令，禁止跳过原生编译测试仅以导入成功充当功能验收：

  1. C++20 4+1 多进程与 HAL 插件构建验证（src/robot_app/Makefile）：
make -C src/robot_app all
make -C src/robot_app test

其中 all 目标依次构建 libsal_shm.so、5 个 HAL 动态插件（libhal_facri.so、libhal_g2.so、libhal_m20.so、libhal_rp1.so、libhal_ugv_can.so）与 5 个独立可执行程序（robot_supervisor、robot_body_rt、robot_spatial_perc、robot_motion_plan、robot_task_agent）；test 目标编译并执行 test_core_hal_safety_ipc、test_algorithms_and_allocator、test_embodiment_decoupling 三套原生 C++20 回归程序。

  1. Python 单元回归、MuJoCo 4.0.1 与 SIT-F3 联调：
python3 -m pytest tests/unit -q
python3 -m pytest simulation/backend/tests/test_mujoco4_native_contact_fleet.py -q
python3 -m pytest tests/integration/test_factory_4robot_multiprocess_closed_loop.py -q
  1. ROS 2 契约包构建与安装包校验：
source /opt/ros/humble/setup.bash
colcon build --packages-up-to system_app robot_app
python3 tools/deployment/build_runtime.py --help
  1. 前端界面与能力面板构建检查（apps/collaboration_platform/web/）：
npm --prefix apps/collaboration_platform/web run build
npm --prefix apps/collaboration_platform/web run test:capabilities
  1. 感知 PCT 原生第三方算法增量编译（仅依赖变更时）：可通过 tools/deployment/build_pct_sdk.sh 在隔离构建目录编译 gtsam-4.1.1 与 osqp，再使用 tools/deployment/package_pct_sdk.py 打包。

三、基线指纹、第三方来源核验与开发红线

  • 冻结运行配置核验：算法调优前后执行 python3 tools/verification/check_factory_runtime_baseline.py，校验核心参数是否相对 docs/development/factory-runtime-baseline.md 发生非预期漂移。当报出 RUNTIME_BASELINE_SOURCE_DRIFT（如 AGENTS.md 随文档治理演进更新后引发摘要差异）时，必须先比对实际代码差异与后续授权记录，严禁私自篡改 resources/factory-runtime-baseline.json 凑出假 PASS。
  • 第三方源码校验：执行 python3 scripts/verify_sources.py 核对平铺第三方目录与补丁文件的 SHA-256 摘要，不可擅自重写清单散列值消除报错。
  • 并发与资产约束：物理仿真严格一次运行一个 case，按照 resources/server-paths.json 记录独立 case_id 并尊重既有 owner 锁；模型权重、ROS 录包、原始视频及本机临时产物均严禁提交入 Git 版本控制。
