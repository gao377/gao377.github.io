HAL 硬件抽象层与 SalWire v2 协议

IHalDriver 插件 ABI、6 大动态库后端、8192 B state_cmd.shm 与 128 KiB lidar.shm

定位与上下游边界

IHalDriver 与 SalWire v2 共同构成端侧 robot_body_rt 控制进程与外部物理世界之间的唯一双边解耦境界：上游承接 200 Hz 全身参考指令与带外 SafetyFrame 急停覆盖信号，下游对接 MuJoCo 物理仿真共享内存（SIM_SAL）或五型真机硬件总线动态库（REAL_HAL）。通过定长零拷贝线协议、编译期字节断言与单调代际 epoch 校验，端侧核心算法可在仿真与真机硬件之间切换而无需重新编译。

IHalDriver 抽象边界与 6 大动态库插件

src/robot_app/include/robot_app/hal/i_hal_driver.hpp 定义了标准虚基类 IHalDriver 及基于 C 语言符号 create_hal_driver(const char* profile_json) / destroy_hal_driver(IHalDriver*) 的动态加载入口（由 src/robot_app/algorithms/hal/plugin_loader.cpp 运行时按配置名载入 .so）。每型驱动必须强制显式声明自身的运行出身与能力约束：

  • 可信出身标识（HalOrigin）：返回 HalOrigin::SIM_SAL（物理仿真后端）或 HalOrigin::REAL_HAL（实物硬件后端），作为跨层追踪执行真实来源的基础依据。
  • 启动前标定核验（probe_and_verify_calibration）：在 start(epoch, out_error) 拉起控制循环前，强制核查预期 URDF SHA-256 摘要与现场标定文件是否完整匹配，校验失败则拒绝激活驱动输出。
  • 五种标准控制模式（JointCtrlMode）：支持 kDisabled（失能）、kPositionPd（位置 PD 伺服）、kVelocityPd（速度 PD 伺服）、kTorque（纯力矩前馈）与 kDampingHold（高阻尼安全保持），并统一暴露紧急保护入口 engage_safe_stop()。

SalWire v2 定长零拷贝共享内存协议

在所有仿真场景（sal_transport: "shm_v2"）中，仿真器后端与各机器人 robot_body_rt 进程通过 /dev/shm/embodied_sal/<run_id>/<robot_id>/ 目录下的两个固定尺寸 mmap 文件交换高频姿态、关节指令与三维点云。所有结构体在 src/embodied_core/include/embodied_core/sal_wire.hpp 中均以 #pragma pack(push, 1) 紧密排列并附带编译期 static_assert 字节核查与末端 CRC32 IEEE 校验：

输入验证、帧新鲜度门禁与双层安全防线

src/robot_app/modules/sensor_adapters/domain.hpp 中的 SensorAdaptersDomain 对每条读入的 HalSample 执行严格检验，不放行任何脏数据进入控制回路：

  1. 数值与结构完整校验：检查 verify_sal_sample_wire() CRC32 一致性，以及 q、dq、IMU 和位姿分量是否全部为有限浮点数，异常直接递增 nonfinite_rejected 并拒绝更新总线。
  2. 代际（epoch）与帧序防回退检查：拒绝与 expected_epoch_ 不一致或序列号倒退（stale_seq_dropped）的历史残帧，防止重连或仿真重启瞬间发生位置阶跃跳变。
  3. 带外急停覆盖权：不论上层规划软件发送了何种 SalCommandWire 目标，一旦 protection_runtime 通过 18749 UDP 端口接收到针对本机位掩码的 SafetyFrame 急停信号或检测超时触发 LOCAL_HOLD，body_gateway 将强制置位 estop_hold = true 并对下发执行器施加零速度及安全阻尼控制。
