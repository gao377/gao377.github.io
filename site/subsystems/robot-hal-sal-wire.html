HAL 硬件抽象层与 SalWire v2 协议

IHalDriver 插件 ABI、6 大动态库后端、8192 B state_cmd.shm 与 128 KiB lidar.shm

01 · 需求来源与工程背景

端侧 200 Hz 运动控制系统需要同时运行在 MuJoCo 物理仿真环境与五型异构真机硬件总线上。若直接把仿真共享内存结构体或特定厂商 SDK 编译进 robot_body_rt 主程序，会造成三类工程风险：

  1. 驱动耦合导致二进制分叉：仿真或任一厂家通信协议变动都会迫使核心规划与控制模块重新编译，且容易把仿真特有字段泄漏进真机控制路径。
  2. 脏帧、错代与未标定飞车隐患：仿真复位或总线重连瞬间，若传感器通道混入 NaN 浮点、倒退序列号 seq 或上一代际 epoch 残留帧，PD 控制器会在单个 5 ms 周期内输出巨大力矩阶跃。
  3. 带外急停无法抢占软件轨迹：当操作员按下无线急停或单机触发局部保护时，必须由硬件出口层的最后一道关口在写入总线前强制覆写目标，确保高层规划指令无法覆盖安全停机信号。

02 · 架构位置与总功能流

IHalDriver 与 SalWire v2 位于单机实时进程 robot_body_rt（P0）与外部物理世界之间，构成唯一双边解耦边界：上游经 SensorAdaptersDomain 接收采集样本并经 BodyGatewayDomain::step_200hz 汇出关节参考指令，下游通过 HalPluginLoader 动态载入的 .so 插件对接 /dev/shm/embodied_sal/<run_id>/<robot_id>/ 共享内存（SIM_SAL）或真机硬件驱动（REAL_HAL）。

src/robot_app/processes/body_rt_main.cpp 在进程启动阶段严格按序执行以下四步前置校验，任一步失败即返回错误码 2 并退出而不进入控制循环：

  1. 动态载入 C ABI 插件：HalPluginLoader::load（src/robot_app/algorithms/hal/plugin_loader.cpp）以 dlopen(..., RTLD_NOW | RTLD_LOCAL) 加载插件，解析 create_hal_driver 与 destroy_hal_driver 符号并实例化驱动。
  2. 现场标定指纹核验：调用 probe_and_verify_calibration(expected_urdf_sha256, ...) 核对预期 URDF SHA-256 摘要与现场标定文件一致性。
  3. 代际激活与自由度匹配：调用 start(epoch, err) 激活驱动，并比对 query_hardware_caps().active_dofs 与 EmbodimentSpecPod.active_dofs 是否一致。
  4. 周期读写与急停覆盖：SensorAdaptersModule 读入样本并过滤脏帧，BodyGatewayModule 在 200 Hz 下合流 ActionExecOutPod、PolicyRunner 与带外 SafetyStatusPod 后写入硬件。

03 · 核心原理与内部机制

SalWire v2 定长零拷贝线协议与校验和

在 sal_transport: "shm_v2" 仿真场景下，仿真侧与 robot_body_rt 共享两个固定大小的 mmap 文件（src/embodied_core/include/embodied_core/sal_wire.hpp）：state_cmd.shm（8192 B）上半区放置 SalSampleWire（1472 B，魔数 0x454D5341 "EMSA"，序列锁偏移 0、载荷偏移 8 B），下半区放置 SalCommandWire（2052 B，魔数 0x454D5343 "EMSC"，序列锁偏移 4096、载荷偏移 4104 B）；lidar.shm（131072 B / 128 KiB）放置 SalLidarWire（96068 B，魔数 0x454D4C44 "EMLD"，最多 6000 个 16 B SalLidarPointXYZI 点云）。所有线结构体均以 #pragma pack(push, 1) 紧密打包，并在编译期由 static_assert 锁定精确字节尺寸与尾部 crc32_ieee 偏移，彻底消除跨语言、跨编译单元的结构体填充歧义。

四级传感器防腐过滤与带外急停覆盖

  • 四级防腐拦截（SensorAdaptersDomain）：src/robot_app/modules/sensor_adapters/domain.hpp 对每帧 HalSample 依次校验 verify_sal_sample_wire() CRC32 校验和、全部关节/IMU/位姿分量有限浮点合法性（异常递增 nonfinite_rejected）、与 expected_epoch_ 的代际一致性，以及帧序号单调性（倒退丢弃并递增 stale_seq_dropped），绝不放行脏数据进入内部 BodyRtBus。
  • 双时钟隔离：SalSampleWire 携带仿真物理时间 sim_time_ns，SalCommandWire 携带宿主机单调时间 host_monotonic_ns，严禁混用两类时钟判断消息新鲜度。
  • 带外 32 B SafetyFrame 优先权：src/embodied_core/include/embodied_core/safety_frame.hpp 定义固定 32 B UDP 安全帧（魔数 0x454D5346 "EMSF"，监听端口 18749）。一旦 protection_runtime 触发急停或 LOCAL_HOLD，BodyGatewayDomain::step_200hz（src/robot_app/modules/body_gateway/domain.hpp）强制置位 estop_hold = true（对应 kCmdFlagEstopHold）并对执行器下发零速与 kDampingHold 高阻尼安全保持，无条件覆盖上层运动目标。

04 · 软件工程实现范式与合规审视

本子系统体现 P-III 动态插件策略桥接与防腐层边界范式：

  • C ABI 插件工厂与最小可见性隔离（HalPluginLoader）：src/robot_app/include/robot_app/hal/i_hal_driver.hpp 通过纯虚基类 IHalDriver 与 extern "C" 工厂函数 create_hal_driver/destroy_hal_driver 隔离核心二进制与插件实现；HalPluginLoader 使用 RTLD_LOCAL 防止多插件间符号污染，并在析构期自动调用 driver_->close() 与 destroy_fn_ 避免资源泄漏。
  • 不可信输入防腐边界（SensorAdaptersDomain）：在 P0 最前端设立无状态检验过滤器，将未校验的物理/网络字节流阻挡在领域计算之外。
  • 可信出身自证（HalOrigin）：驱动必须显式返回 HalOrigin::SIM_SAL 或 HalOrigin::REAL_HAL，由下而上贯通 ChildHeartbeatPod 与 TeamVerifier，防止仿真后端伪装成真机回执。
评估维度 合规状态 工程依据与审视说明
1. 领域纯洁性与依赖倒置 PASS robot_body_rt 核心仅依赖 IHalDriver 抽象接口，SalWire 与真机总线实现下沉至 .so 插件
2. 契约完备性与边界防呆 PASS #pragma pack(push, 1) + static_assert + CRC32 + URDF SHA-256 核验 + SensorAdaptersDomain 四级过滤
3. 状态机与生命周期确定性 PASS load -> probe_and_verify_calibration -> start(epoch) -> read/write -> engage_safe_stop -> close 严格有序
4. 实时内存与并发安全性 PASS 定长 mmap 零堆分配传输；BodyGatewayDomain::step_200hz 标记 noexcept 并配合 SeqLock 无阻塞读写
5. 离线可测性与失败留痕 PASS test_core_hal_safety_ipc 离线校验字节布局、CRC32 篡改拒收、帧序倒退统计与 SafetyFrame 解码
6. 单真源约束与过渡债务透明度 SCOPED 线协议收口于 sal_wire.hpp 与 safety_frame.hpp；libsal_shm.so 已在 SIM 验证，五型真机 libhal_*.so 插件需独立绑定现场标定与 L4 物理验收

06 · 实测效果与能力边界

  • 离线协议与物理工厂验证（L1 / L3）：L1 原生单元测试 test_core_hal_safety_ipc 验证了 SalSampleWire（1472 B）、SalCommandWire（2052 B）、SalLidarWire（96068 B）与 SafetyFrame（32 B）的精确布局、CRC32 损坏拒收与跨代际拦截；在 L3 级 510/510 纯接触操作及 SIT-F3 四机集成测试中，libsal_shm.so 稳定支撑 200 Hz 关节交互与 10 Hz 点云读取。
  • 能力边界声明：libsal_shm.so 仅报告 HalOrigin::SIM_SAL，任何在 MuJoCo 仿真环境下通过的测试均不可直接替代 libhal_facri.so 等 REAL_HAL 真机插件在 L4 现场的实机总线、延迟与急停硬件测试。
