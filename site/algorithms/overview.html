01 · 算法核全栈位置与调用边界

算法核层分布于单机 4+1 实时运行时的 P0、P1 与 P2 进程内部（src/robot_app/algorithms/ 与各运行模块域目录），以及独立外部模型推理网关 apps/model_gateway/。上游承接经 SensorAdaptersDomain 帧新鲜度校验、防倒退及 epoch 核验的传感样本，以及 LocalTaskRuntime 派发的原子能力目标；下游向 ActionExecutor 与 body_gateway 输出受物理限幅保护的关节参考、底盘扭转速度与柔顺导纳修正量。

全站所有算法模块均严守三条架构红线：传感观测与位姿估计严格归属感知与状态估计层、规划与控制核严禁越权读取仿真真值、下肢步态资格严禁跨本体型号继承。系统整体平面划分、通信总线及冻结基线参见 架构总览、组件地图 与 运行基线与冻结配置。

03 · 软件工程实现范式与合规总览矩阵

对照源码组织可见，系统算法层并非单一语言堆砌，而是按「计算实时性、内存安全边界与外部依赖隔离」严格分层，现行代码树客观包含四类工程实现状态：

  1. 纯 C++20 零分配实时核：运行在 P0、P1 与 P2 进程实时主环内，包括 PolicyRunner、VoxelIcpLocalizer、HybridAStar、MppiLocalPlanner、PlanarAdjustment、UpperBodyPlanner、DlsIkSolver、AprilTagTracker 与 LidarReflexRing。该类算子普遍采用值语义配置、预分配固定缓冲、noexcept 状态推进与单写者无锁 IPC 交接，杜绝实时环动态内存抖动。
  2. Python 六层整洁领域核：将高维业务语义、纯数学算子与外部适配器隔离于 contracts/、domain/、application/、infrastructure/ 分层中，代表实现包括 ConvergentTerminalServo、WrenchObserver、TaskAdmittanceSession、TouchdownGuard、SalLidarIngress 与 ResponseSampling，通过 assembly.py 与受控原生绑定联合调度，构成当前 C++20 / Python 双栈受控演进（HYBRID）的主体。
  3. SIM_ONLY 隔离标记路径：仅用于仿真动力学补偿与验证准入的模块，包括 FacriMjlabPolicy（src/robot_app/backends/facri/mjlab_policy.py）、src/robot_app/backends/facri/bound_control.py 及 operation_snapshot（simulation/backend/src/embodied_sim/modules/mujoco_world/upper_inertia.py 中的 FixedUpperInertia）。入口处均执行强制 origin == 'SIM' 校验，严禁渗透至 REAL 真机运行链。
  4. 特性分支未并入（BRANCH）：五阶段工件超分与细微螺母缺陷检测核心算子 pft_workpiece_sr 当前驻留于特性分支 feat/workpiece-detection-debug-20261124（提交 d3cddf263），尚未合入当前 c919_ground_scene_modeling 主线代码树。
