双臂规划与柔顺操作

仅位置约束 49 候选 DLS 逆解、Minkowski 扫掠检验与纯臂雅可比纯接触导纳

01 · 需求来源与工程背景

在废弃仿真 <weld> 等式吸附外挂后，双臂柔顺抓取与精密安置暴露出四项制约任务成功率的物理与优化瓶颈：

  1. 全姿态强约束 Pink/Clarabel 逆解频繁失败：工位操作空间狭小且受限于双足站位误差，若强行要求双夹爪末端同时满足全 6 自由度位姿（含 10° 姿态容差）并叠加双臂 14 个关节位置限位，求解器极易在运动学奇异区或工作空间边缘无解停摆。
  2. 传统离散碰撞检测的「穿隧」风险：仅对时间采样点做静态网格碰撞检查时，高速机械臂连杆或手部在 20 ms 步长间隔内可能直接跳过薄壁货箱侧板或设备棱边而未被检出。
  3. 腰部隐式阻尼污染末端接触力反演：若沿用包含腰部关节的全身雅可比计算末端广义力，躯干大阻尼与关节摩擦会混入臂端力估计，导致无力矩传感器场景下无法分辨「工件刚着台」与「躯干内部阻尼拉扯」。
  4. 过早松爪导致悬空跌落：在纯物理接触抓放中，若仅按名义位置到达判定就打开夹爪，极易因几毫米高度偏差令工件在空中松脱倾翻。

针对上述问题，仓库冻结采用唯一的 native_full / PlanningCore 管线：放弃末端姿态约束与双臂 14 轴位置界限，转为仅约束末端位置的 17 轴加权阻尼最小二乘（DLS）与 49 组横向网格候选搜索；执行前强制通过 Minkowski 连续扫掠检验；接触阶段采用显式剔除腰部关节的纯 7 轴臂雅可比力观测器配合作业分阶段导纳剖面与 TouchdownGuard 垂直触底守卫。

02 · 架构位置与总功能流

上身操作模块运行在无 <weld> 辅助的纯物理接触基准上，横跨 manipulation_runtime（P2 进程）与 action_executor（P0 进程）：上游消费 BodyStabilityMonitor 确认的躯干停稳门禁、目标 TCP 位置以及持物上下文；在规划阶段完成 17 轴 49 候选顺序逆解、速度连续种子插值与连续扫掠碰撞核验后，经 traj_slot.shm 下发同步时间序列；执行期由 WrenchObserver 与 TouchdownGuard 实施 200 Hz 外环柔顺修正与触底判稳释放。全局冻结配置见 运行基线与冻结配置，物理接触垫片细节见 MuJoCo 4.0.1 仿真引擎。

03 · 核心原理与机制推演

3.1 仅位置约束 17 轴加权 DLS 与 49 候选顺序搜索

UpperBodyPlanner 与 DlsIkSolver（src/robot_app/algorithms/planning_core/upper_body_planner.hpp、upper_body_planner.cpp 与 dls_ik_solver.hpp）承担腰臂联合规划，其核心数学结构与冻结约束如下：

  1. 关节分工与腰部刚度惩罚阶梯：规划向量维度 kUpperBodyDofs = 17（3 轴腰部 + 左/右臂各 7 轴）。遵照冻结设计，双臂 14 个肩/肘/腕关节全部解除位置限位（enforce_limits = false），仅对腰部保留唯一单真源三轴硬范围（resources/facri-upper-joint-limits.json：yaw ±40°、pitch [-10°, +30°]、roll ±25°），并施加显式非均匀惩罚权重 Wwaist=diag⁡(1.0,10.0,100.0)W_{\text{waist}} = \operatorname{diag}(1.0,\, 10.0,\, 100.0)（yaw : pitch : roll = 1 : 10 : 100）：

Δq=(Jpos⊤Jpos+λ2I+Wwaist)−1Jpos⊤epos\Delta q = \left(J_{\text{pos}}^{\top} J_{\text{pos}} + \lambda^2 I + W_{\text{waist}}\right)^{-1} J_{\text{pos}}^{\top} e_{\text{pos}}

其中 JposJ_{\text{pos}} 为剔除旋转行后的纯位置雅可比，阻尼 λ=0.015\lambda = 0.015、单点最大迭代 48 次、分段末端位置误差容限 max_segment_pos_err_m = 0.020 m。高昂的侧倾权重（roll = 100.0）迫使工作空间需求优先由手臂与腰部偏航消化，严防躯干侧倾危及双足平衡。

  1. 49 组 ±30 mm 网格序列搜索（plan_cartesian_49）：从同一捕获状态出发，左右手各自生成中心与 ±X / ±Y / ±Z 30 mm 共 7 个微扰候选，按「原目标对 (0, 0) -> 单手微扰 -> 双手组合（共 7 × 7 = 49 组）」顺序逐一构建左右手公共最小加加速度（Minimum-Jerk）时间表（固定 20 ms 步长、最多 kMaxTcpSegments = 100 段、kMaxPackedWaypoints = 128 路点）。任何一段逆解超差（> 20 mm）或失败立即放弃整组候选，仅执行首个全段成功候选，不采用前缀截断拼接，亦不再搜索 ±5° 角度候选。
  2. 持物中点几何、单次机身补偿与按钮前缀逆放：搬运期调用 compute_held_dual_tcp_targets 使工件标定双抓点中点贴合双 TCP 中点且连线以最小旋转跟随双 TCP 连线（允许手距变化与两端均分误差，不跟随单手腕自转）；每条解锁腰部的空间轨迹完成后，经 state_estimation 检查机身相对偏移若达到 2 cm 或 3°（kDriftCompPosThresholdM / kDriftCompRotThresholdRad），则向同一原空间目标执行单次漂移补偿（不循环）；按钮退手直接启用 REVERSE_PREFIX_REPLAY 逆序回放本次已发安全关节前缀而不重求 IK。

3.2 保速种子插值、Minkowski 扫掠检验与纯臂力控着陆

  1. 速度连续种子插值与 Bernstein 扫掠防穿隧：在 src/robot_app/modules/manipulation_runtime/domain/trajectory/seed.py 中，轨迹节点重采样采用 CubicHermiteSpline 严格保持关节速度 C1C^1 连续，消除线性插值在路点拐角引起的力矩尖峰；随后 DeviceCollisionQuery（src/robot_app/modules/manipulation_runtime/infrastructure/native_bindings/device_collision.py）对校核手部连杆、工装与平移工件构造相邻离散构型间的 Minkowski 凸包扫掠体，并利用关节链 Bernstein 多项式速度上界自适应中点二分细分时间区间，直到剩余间隙与分段不确定度满足几何安全门限，从数学上杜绝高速轨迹「穿墙越过」箱壁。
  2. 纯 7 轴臂雅可比力观测（WrenchObserver）：位于 src/robot_app/modules/manipulation_runtime/domain/control/wrench_observer.py，构造显式剥离全部腰部关节的纯 7 自由度单臂 Pinocchio 雅可比矩阵 Jarm∈ℝ6×7J_{\text{arm}} \in \mathbb{R}^{6 \times 7}。对经死区过滤（deadband = 0.12 Nm）和一阶指数平滑（ema_alpha = 0.22）后的关节估计力矩 τfilt\tau_{\text{filt}}（无质量上肢 SIM 配置下重力项显式置零），采用解耦阻尼伪逆反演操作坐标系末端广义外力：

fee=(Jv⊤Jv+λlin2I)−1Jv⊤τfilt(λlin=0.08),τee=(Jω⊤Jω+λang2I)−1Jω⊤τfilt(λang=0.35)f_{\text{ee}} = \left(J_{v}^{\top} J_{v} + \lambda_{\text{lin}}^2 I\right)^{-1} J_{v}^{\top} \tau_{\text{filt}} \quad (\lambda_{\text{lin}} = 0.08), \qquad \tau_{\text{ee}} = \left(J_{\omega}^{\top} J_{\omega} + \lambda_{\text{ang}}^2 I\right)^{-1} J_{\omega}^{\top} \tau_{\text{filt}} \quad (\lambda_{\text{ang}} = 0.35)

  1. 分阶段导纳与 TouchdownGuard 触底守卫：TaskAdmittanceSession（src/robot_app/modules/manipulation_runtime/domain/control/admittance.py）按任务阶段加载四套二阶质量-阻尼-刚度导纳剖面。在安置末段激活 PLACE_TOUCHDOWN_PROFILE 及其 TouchdownGuard：当行程进度达到 90%（seek_start_ratio）而向上反力未及 0.45 N 时，启动最高 0.008 m 深度、0.015 m/s 速率的轻柔下探微寻；仅当实时监测到连续满足垂直接触反力 fz≥0.90Nf_z \ge 0.90\;\text{N} 且各关节速率 <= 0.15 rad/s 并平稳驻留 dwell_s = 0.08 s 后，才确认可靠着台并放行双爪开爪释放。

04 · 软件工程实现范式与合规审视

上身操作层体现了「C++20 UpperBodyPlanner 实时规划核 + Python 柔顺/扫掠领域算子」双栈协作范式（HYBRID）：

  • 值语义算子管道（UpperBodyPlanner & DlsIkSolver）：规划器无隐藏全局状态，输入起止状态与配置结构体即返回完整 UpperPlanResult；所有 49 候选生成、公共时间轴插补与 20 ms 打包在同一原语内原子完成。
  • 不可变策略配置对象（AdmittanceProfile / TouchdownGuard）：四套导纳剖面以 @dataclass(frozen=True) 声明并在 __post_init__ 完成正定性与有限值校验；TaskAdmittanceSession 仅绑定单一轨迹生命周期并支持依赖注入自定义 WrenchObserver。
  • 安全门禁与输入验证前置（native_full_inputs.py & DeviceCollisionQuery）：将支持面边界、场景几何版本及 Minkowski 扫掠检查全部前置于轨迹下发前，绝不在执行期插手动态重规划掩盖几何失效。
评估维度 审阅结论 客观工程依据
1. 领域纯洁性与依赖倒置 PASS UpperBodyPlanner、WrenchObserver 与 TaskAdmittanceSession 均不依赖 ROS 2 消息总线与底层电机驱动
2. 契约完备性与边界防呆 PASS native_full_inputs.py、AdmittanceProfile 与 DeviceCollisionQuery 在构造/规划入口拦截缺项与越界
3. 状态机与生命周期确定性 PASS 49 候选整组原子成败、TouchdownGuard 0.08 s 驻留门禁与 REVERSE_PREFIX_REPLAY 回退边界严密
4. 实时内存与并发安全性 HYBRID UpperBodyPlanner 在 C++20 中运行；DeviceCollisionQuery、WrenchObserver 与导纳会话仍驻留 Python 运行域
5. 离线可测性与失败留痕 PASS 支持纯内存数值回放、COAL 离线扫掠审计及 C 站位历史失败对照留存
6. 单真源约束与过渡债务透明度 HYBRID 腰限收口 resources/facri-upper-joint-limits.json 单真源；客观标明 C++20 规划核与 Python 算子双栈协作边界

06 · 实测效果与能力边界

上述冻结设计已获得三层对照数据验证（证据层级严格按 五级验证阶梯 区分，不混同外推）：

  • 关键约束消融对照（20 组典型输入）：在完全相同的 20 组生产输入上，仅放开双臂 14 轴位置限位但保留 10° 末端姿态约束时通过率为 0 / 20；在保留腰部硬界与放开双臂的同时转为仅位置约束后，原目标通过率跃升至 20 / 20。
  • MuJoCo 4.0.1 零 <weld> 纯物理接触基准（510 / 510）：在取消全部刚性吸附外挂的纯物理双层垫片仿真下，合并 70 / 70 调试与 440 / 440 验证样本实现 510 / 510（100.0%）全通过（覆盖 204 / 204 次按压、153 / 153 次取料与 153 / 153 次柔顺着台放置），累计 859,974 个控制 tick（6,879,792 个 0.625 ms 子步），离线 589,400 次 COAL 扫掠碰撞样本穿插数为 0，指端最大实测速率 0.15716 m/s <= 0.20 m/s，悬停 1.25 s 工件滑移跌落 <= 0.0020 mm。
  • 4 机 40 操作 / 180 阶段与 C 站位历史对照：早期 C 站位曾暴露 4 项下放几何失败与时长异常（历史失败证据完整保留）；随后将 C 站位前移 10 cm（累计 operation_advance_m = 0.262 m）并设定释放抬高 release_height_m = 0.05 m（支撑高度不变）后，4 机完整 40 操作 / 180 阶段离线数值全数通过。
