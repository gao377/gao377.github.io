下肢策略与状态估计

FacriMjlabPolicy 推理链、非对称斜率限幅、operation_snapshot 惯性切换与 IMU 判稳

01 · 需求来源与工程背景

双足人形机器人支撑多边形远窄于轮式底盘，下肢策略与上身状态估计同时面临三类严峻的物理与实时约束痛点：

  1. 加减速踝关节俯仰振荡与冲击倾覆：上层导航或操作重定位下发阶跃速度指令（如从 0 突跳至 0.2 m/s 或急停归零）时，直接送入强化学习步态策略会诱发单周期步幅越界、躯干失稳倾倒以及停稳阶段踝俯仰来回振荡。
  2. 工位弯腰操作引发的重心耦合与全局冻结失稳：若全程冻结上肢惯性并强行锁死动力学响应，行进转向时上肢离心力矩失真会拖垮双足平衡；反之若在工位操作期间保留未补偿的满载上肢惯性扰动，大范围弯腰伸臂又会冲击腿部平衡策略的观测分布。
  3. 跨模态异步抖动与假停稳误动作：双臂抓取与按键启动瞬间若躯干仍在微幅晃动，或上肢参考量与 IMU 时间差过大，极易导致指垫错位甚至空抓跌落；此外，旧版全量静力限幅器在仿真策略轴微幅越界时产生误报停机，掩盖了真实控制表现。

围绕上述痛点，下肢与状态估计层确立了明确量化目标：下肢推理稳定运行于 50 Hz（20 ms 周期，匹配 0.005 s 仿真物理步长与 control_decimation = 4）、标准步态周期 0.8 s、上肢参考时效上限 100 ms；BodyStabilityMonitor 要求 1.0 s 滑窗内采样延迟 <= 40 ms、最大间隔 <= 80 ms 且躯干旋转总角 <= 10°，以此作为双臂启停的唯一因果门禁。

02 · 架构位置与总功能流

下肢运动控制与状态估计驻留于端侧 P0 实时进程（robot_body_rt）与 FacriBodyBackend 适配边界之间：上游消费经 SensorAdaptersDomain 时间戳校准的 IMU 四元数/角速度、29 自由度关节位置与速度反馈、以及 100 ms 内有效的上肢参考量；经特征编码与 50 Hz 策略推理后，依次穿过速度准入、非对称双向斜率限幅器与连续倾角衰减器，最终向 SAL / HAL 写入 29 轴位置与阻抗目标。

与此同时，StateEstimationDomain 并行对 IMU 缓存与 17 自由度上身正解（FK）做插值融合，驱动 BodyStabilityMonitor 向 P2 manipulation_runtime 提供躯干停稳门禁与机身相对位移基准（用于作业后单次 2 cm / 3° 机身偏移补偿）。完整 4+1 进程拓扑见 单机 C++20 4+1 多进程实时架构。

03 · 核心原理与机制推演

3.1 双栈同义推理：47 -> 12 与 10×100 -> 29

系统在 Python SIM 隔离封装（src/robot_app/backends/facri/mjlab_policy.py）与 C++20 多进程常驻核（src/robot_app/algorithms/policy_infer/policy_runner.hpp）中保持同一控制语义：

  • Python SIM_ONLY 策略封装（FacriMjlabPolicy）：接收 47 维单帧观测（躯干角速度、投影重力、速度指令、正余弦步态相位、腿部位置误差、腿部速度与上一拍动作），输出 12 维腿部关节绝对位置指令。源码加载阶段强制校核 policy.onnx 与 YAML 部署配置的 SHA-256 哈希，且硬性限定 origin == 'SIM'——一旦在 REAL 真机配置下实例化立即抛出 FACRI_MJLAB_REAL_NOT_QUALIFIED 阻断运行。动作解码严格遵循训练缩放关系：

αact=0.25τlimkp,qabs=qnom+αact⊙a\alpha_{\text{act}} = \frac{0.25\,\tau_{\text{lim}}}{k_p}, \qquad q_{\text{abs}} = q_{\text{nom}} + \alpha_{\text{act}} \odot a

其中 qnomq_{\text{nom}} 为 default_angles，τlim\tau_{\text{lim}} 为 effort_limits，kpk_p 为关节刚度，支持 legacy_xy_v1 与 command_norm_v1 两种静止相位门控，并在启用 urdf_limits 投影时将指令截断在 URDF 物理上下界内。

  • C++20 常驻推理核（PolicyRunner 与 ObservationEncoder）：运行于 robot_body_rt 实时循环，统一维护 kPolicyJointCount = 29（kLegDofs = 12 + kUpperDofs = 17）及 kHistoryLength = 10 × kFrameObsDim = 100 = kTotalObsDim = 1000 维时序栈（src/robot_app/algorithms/policy_infer/observation_encoder.hpp），强制核验 kUpperRefMaxAgeNs = 100 ms。推理后端优先经 dlopen 挂载 onnxruntime，缺省时无缝降级至内建 OnnxProtobufMlp 或固定确定性核，并挂载 SimPositionExcursionGuard 对非策略关节连续超差 100 ms（kSimPositionExcursionNs）执行保护截断。

3.2 非对称双向斜率限幅与倾角连续衰减

在 src/robot_app/backends/facri/control_cycle.py 中，_slew_sim_velocity 对 command_norm_v1 模式的平面速度指令 (vx,vy,ωz)(v_x, v_y, \omega_z) 实施两级非线性整形（阈值由 src/robot_app/backends/facri/bound_control.py 的 command_admission 约束在上限 (0.85, 0.20, 0.40) 之内）：

  1. 连续跌倒倾向衰减器（Stumble-Tilt Governor）：由测量四元数提取躯干总倾角 θtilt=2arcsin⁡(min⁡(1,qx2+qy2/∥q∥))\theta_{\text{tilt}} = 2\arcsin(\min(1, \sqrt{q_x^2+q_y^2}/\|q\|))，在区间 [0.14,0.24]rad[0.14,\, 0.24]\,\text{rad} 内实施线性衰减：

g(θtilt)=clip⁡(0.24−θtilt0.24−0.14,0,1),vgov=g(θtilt)vrawg(\theta_{\text{tilt}}) = \operatorname{clip}\!\left(\frac{0.24 - \theta_{\text{tilt}}}{0.24 - 0.14},\; 0,\; 1\right), \qquad v_{\text{gov}} = g(\theta_{\text{tilt}})\, v_{\text{raw}}

当躯干倾斜超过 0.14 rad（约 8.0°）时平滑压低期望线/角速度，达到 0.24 rad（约 13.8°）时将指令归零以优先保稳。

  1. 非对称加速/制动斜率与低速归零锁定：判定当前步处于减速或反向制动条件（pnorm>10−6p_{\text{norm}} > 10^{-6} 且 tnorm<pnormt_{\text{norm}} < p_{\text{norm}} 或点积为负）后，加速段采用温和步长 SIM_ACCEL_LINEAR_STEP_MPS = 0.022 m/s（偏航 0.04 rad/s），而减速段采用快步长 SIM_DECEL_LINEAR_STEP_MPS = 0.06 m/s（偏航 0.08 rad/s）；当目标为零速且剩余线速度降入 SIM_DECEL_GATE_SNAP_MPS = 0.055 m/s（偏航 0.055 rad/s）以内时果断归零锁定，彻底消除低速临界区来回踏步导致的踝俯仰振荡。

3.3 operation_snapshot 操作期惯性冻结与 BodyStabilityMonitor 判稳

为兼顾行进稳定性与工位操作精度，仿真物理层启用唯一冻结配置 upper_inertia_mode=operation_snapshot（实现于 simulation/backend/src/embodied_sim/modules/mujoco_world/upper_inertia.py 的 FixedUpperInertia 与 upper_position.py）：

  • 交接边沿单次快照切换：初始导航阶段不冻结上肢，保持真实连杆质量与正常腰部动力学。当工位原生解锁确认后首次释放腰/臂时，FixedUpperInertia.freeze() 通过 mj_kinematics 与 mj_comPos 捕获此刻相对底座 base 的整套上肢质量分布、偏心质心与特征主惯量张量并折叠至根体，随后将操作期上肢腰臂切为理想执行并保留腰部三轴硬范围。
  • 局部锁不重捕获、重锁原子恢复：作业中间的按钮局部腰锁或重复解锁不会触发重新捕获；仅当完整腰臂重锁确认后，在下一物理步积分前执行 restore()，通过独立 scratch MjData 重新调用 mj_setConst，完整恢复原 body_mass、body_ipos、body_iquat、body_inertia、dof_armature 与原腰部执行驱动（使驱动缓存失效并重用既有 apply_device_command），绝不重置 qpos / qvel / time。取消或失败本身不直接切换状态，保持每机独立。

在进入上身操作前，BodyStabilityMonitor（src/robot_app/modules/state_estimation/domain/stability.py）对融合后的机身质心与姿态执行 1.0 s 滑窗因果判稳：必须同时满足最新采样年龄 <= 40 ms（MAX_AGE_NS）、相邻样本间隔 <= 80 ms（max_gap_ns）、时间戳与 epoch 严格单调递增、期望速度处于零速带（|vi|≤10−5|v_i| \le 10^{-5}）、以及窗内质心漂移范围与总旋转摆幅不超过配置阈值（其中旋转范围硬上限为 10°），方才锁定并递增因果代际 standing_generation 放行上臂操作。

04 · 软件工程实现范式与合规审视

本域呈现典型的「C++20 实时策略核 + Python SIM_ONLY 防腐隔离边界 + 因果状态机」工程结构：

  • 策略模式与动态运行时桥接（PolicyRunner）：将观测编码（ObservationEncoder）与底层推理后端解耦，支持 onnxruntime 动态装载、内建 OnnxProtobufMlp 与固定核平滑降级，同时严格禁用控制循环内堆分配。
  • 防腐隔离护栏（FacriMjlabPolicy & bound_control.py）：将 SIM 专属的 47 维步态映射、URDF/YAML SHA-256 校验、有限浮点检查与 command_admission 集中在边界适配层，以 FACRI_MJLAB_REAL_NOT_QUALIFIED 硬异常阻断跨模式误用。
  • 因果代际状态机（BodyStabilityMonitor & FixedUpperInertia）：BodyStabilityMonitor 显式校验源时间戳因果序与 standing_generation 租约，拒绝未来时间戳回读；FixedUpperInertia 将危险的模型结构修改（mj_setConst）限制在独立 scratch 与状态边沿，确保数值可逆。
评估维度 审阅结论 客观工程依据
1. 领域纯洁性与依赖倒置 PASS PolicyRunner 与 BodyStabilityMonitor 均与 ROS 2 传输及仿真引擎 API 彻底解耦，仅依赖值对象与纯数组输入
2. 契约完备性与边界防呆 PASS 强制执行 SHA-256 指纹核验、origin == 'SIM' 守门、有限浮点校验与 epoch 单调递增防串包
3. 状态机与生命周期确定性 PASS standing_generation 代际失效与 operation_snapshot 重锁边沿恢复状态迁移清晰，无隐式旁路
4. 实时内存与并发安全性 PASS C++20 侧 ObservationEncoder 与 PolicyRunner 在实时环零动态分配；BodyStabilityMonitor 使用有界滑窗队列
5. 离线可测性与失败留痕 PASS 策略推理与判稳机均支持纯内存确定性回放；保留 N02 诊断档案、实际计数及失败原因代码
6. 单真源约束与过渡债务透明度 SCOPED 显式标注 FacriMjlabPolicy、斜率限幅及 operation_snapshot 为 SIM_ONLY 隔离简化，不对外宣称 REAL 资格
